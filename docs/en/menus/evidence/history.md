## 1. Purpose

Chronology of runtime events within the available data source.

## 2. How the user operates it

1. Open Evidence > History at /receipts#history.
2. Check for current events; an empty list does not certify no past incidents.
3. Read actor, request, wallet, outcome and references where available.
4. Separate session event, policy change, forwarding, transaction and finality.

## 3. Underlying mechanism

This route belongs to the Evidence family and must be interpreted with identity, policy, exact request and evidence provenance.

## 4. Evidence and limitations

The browser-local bus is not durable cross-user history or an on-chain explorer.

A visible public screen does not equal human runtime acceptance or universal funds protection.
