## 1. Propósito

Presenta acciones propuestas antes de evaluación y handoff.

## 2. Cómo lo usa el usuario

1. Abre Requests y distingue fixture/demostración de una solicitud emitida por un runtime.
2. Lee intención, agente, objeto objetivo, datos del request, presupuesto y contexto de evidencia.
3. Ejecuta solo simulaciones explícitas; no presupongas que una petición puede firmar.
4. Contrasta la solicitud exacta con Decisions y luego History.

## 3. Qué mecanismo representa

La ruta pertenece a la familia Agentes y debe relacionarse con identidad, política, request exacto y fuente de evidencia.

## 4. Evidencia y límites

Solicitar no equivale a aprobar, forwarding ni ejecución de fondos.

La visibilidad de una pantalla pública no equivale a aceptación humana de runtime ni a protección universal de fondos.
